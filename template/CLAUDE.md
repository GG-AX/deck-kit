# CLAUDE.md — <덱 이름> 발표 자료

> deck-kit 양식으로 만든 덱 작업 공간이다.
> (deck-kit 안 `template\`에 있는 이 파일은 양식일 뿐이다 — 복사된 덱 폴더에서만 적용된다.)
> deck-kit(작업 순서·부품·도구 = `SKILL.md`, 디자인 원칙 = `DESIGN.md`)은 Claude Code 플러그인이다. `/deck-kit:deck-kit`로 불러오면 키트 경로가 나온다.

## 세션 규칙 (필수)

- 작업 시작 시 `session.md`(현재 상태·다음 할 일)를 먼저 읽는다. 피드백 기록은 `FEEDBACK.md`.
- 디자인·콘텐츠 원칙: 모든 덱 공통은 deck-kit의 `DESIGN.md`, 이 덱만의 것은 `FEEDBACK.md` 1장. 원칙이 바뀌면 그 한 곳만 고치고(날짜·이유), 다른 문서에 옮겨 적지 않는다.
- 새 피드백은 `FEEDBACK.md` 2장의 해당 슬라이드 표에 적고 처리 상태를 적는다.
- 단계가 끝날 때마다, 그리고 세션을 마칠 때 `session.md`를 현재 기준으로 고친다(지난 내용을 쌓지 않음).
- 사용자와는 한국어로 소통한다. 발표 콘텐츠의 언어는 "이 덱" 칸에 정한다.

## 폴더 — "지워도 되는가" 기준

| 경로 | 용도 |
| --- | --- |
| `presentation/` | **라이브 덱 — 이 폴더만 zip으로 공유한다.** 덱 .html은 하나만 둔다. 안의 경로는 모두 상대 경로. 덱이 쓰는 파일만 둔다 |
| `versions/` | 구버전 코드. 바꾸기 직전에만 남긴다(방법은 `versions/README.md`). 라이브와 같은 사본은 두지 않는다 |
| `source/` | 받은 원본(PPT·문서·사진) — 고치지 않는다 |
| `ai/` | 크레딧을 써서 만든 AI 생성물과 생성 기록 — 지우지 않는다 |
| `work/` | 다시 만들 수 있는 것만(캡처, 추출 결과, 임시 파일) — 지워도 된다 |
| `docs/` | 계획, 받은 피드백 원문 |
| `tools/` | 이 덱에만 쓰는 도구. 공용 도구는 deck-kit의 `tools/` |

## 작업 원칙

- 엔진(`presentation/assets/engine.js`·`engine.css`)은 고치지 않는다. 엔진을 바꿔야 하면 deck-kit에서 고치고 새 버전을 받는다. 이 덱만의 보정과 테마 변경은 `presentation/assets/deck.css`에 한다.
- 오프라인(file://)에서 동작해야 한다: 일반 `<script src>`와 JS 데이터 파일(`window.X = …`)만 쓴다(ES module·fetch 금지). 그림·영상·글꼴은 모두 폴더 안에 둔다.
- 슬라이드 id(`data-src`)는 한 번 정하면 바꾸지 않는다 — 발표자 스크립트가 id에 붙어 있다.
- 발표자 스크립트의 원본은 `presentation/assets/notes.js`다(발표자가 발표자 창에서 고치고 저장함) — 덮어쓰지 않는다.
- PPT가 PowerPoint로 열려 있으면 파일이 잠긴다 → 추출 전에 닫아 달라고 요청한다.
- AI 생성(Higgsfield 등) 크레딧은 쓰기 전에 사용자에게 확인한다. 생성 기록은 `ai/`에 둔다.
- 사용자는 1차 검수부터 참여한다 — 그 전에는 묻지 않고 기본값·가정으로 진행한다(deck-kit `SKILL.md` 작업 순서).
- 피드백을 반영하기 전에 먼저 `versions/`에 백업하고(deck-kit `tools/snapshot.py`), 수정 계획을 보여 준 뒤 고친다.
- 넘기기 전 자체 검수: deck-kit `tools/lint.py`(ERR 없음) + 전 슬라이드 캡처(`tools/shots.py`)를 직접 본다. 최종 확인은 사람이 한다.
